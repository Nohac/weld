# Client cursor feedback

Local Wayland, loopback, native Unix hoisting, and encoded Unix/Iroh hoisting use
the same runtime cursor feedback contract. The source supplies a named shape,
hidden state, or a bounded lossless RGBA image and hotspot. The destination owns
pointer position, hover/capture authority, theme, nominal size, and output scale.
Cursor feedback never enters the video encoder or Bevy's surface/render queue.

Both peers need matching builds. Run `scripts/run-iroh-hoist --codec av1` and
hoist Firefox. Hover links, text fields, page text, and the address bar. Repeat
inside menus and tab previews, then move onto destination SSD and resize a
window. Release resize while remaining on the same edge, then move into client
content: the resize override must clear even if the edge's hover shape did not
change. Reclaim and repeat locally. Compare with
`scripts/run-local-hoist --native`, loopback `Super+H`, and DRM when available.

Named shapes use the destination theme (the parent window system's theme in
nested mode). Custom artwork is scaled so its larger dimension equals the
destination nominal size times output scale; this includes upscaling smaller
sprites, not just clamping oversized ones. Aspect ratio and hotspot are retained.
The source flattens its cursor viewport into at most 128x128 straight-alpha RGBA
pixels. Out-of-image hotspots are clamped during normalization. No lossy video
codec is involved. Malformed wire extents, byte lengths, or hotspots are rejected
before constructing the runtime image. Unsupported DMA-BUF cursor surfaces
still fall back to the default arrow; SHM cursor images are supported.

Only one cursor update per connection is in flight. The receiver acknowledges
receipt/caching immediately, regardless of current hover, so frame decoding
cannot stall cursor feedback. New desired state is coalesced, identical images
are suppressed, and a withdrawn popup's late acknowledgement still releases
credit. A peer withholding acknowledgement stalls its cursor updates, not input,
surface commits, or media. The next ordinary relay poll after two seconds emits
one warning for that outstanding update; no diagnostic timer wakes the desktop.

Mapping controls cursor authority, not preference storage. The receiver retains
the latest cursor across unmap/remap because cursor feedback can overtake older,
video-delayed mapping commits. While unmapped it cannot select that cursor.
Destroy, withdrawal, and disconnect discard the retained state. Storage is at
most 64 KiB per known surface that has supplied a bitmap, including temporarily
unmapped surfaces. A remap without fresh feedback can briefly reuse its previous
shape until a source enter/reset is collected and delivered; this avoids losing
a newer cursor permanently to an older delayed unmap.

Feedback generated by input late in a host iteration may be collected on the
next iteration. A valid pointer route with no cached image shows the default
arrow, never an implicit hidden cursor. Local desktop and remote controllers use independent native input contexts.
Application seat bindings arbitrate ownership so a remote constraint cannot
capture the desktop pointer.
Cursor-surface frame-callback-driven animation remains a separate host feature;
explicit cursor commits are forwarded, but this change does not introduce a
new cursor animation clock or unconditional frame callbacks.

## Pointer locking and hiding

Weld advertises `pointer-constraints-unstable-v1` alongside its existing
`relative-pointer-unstable-v1` support. A lock freezes the pointer position and
keeps delivering relative movement. Confinement limits movement to the committed
surface input/constraint region. Physical DRM supports both; nested validation
supports locking when its parent permits it, and declines child-region
confinement.

A client hides its cursor separately with `wl_pointer.set_cursor` and a null
surface. Locking preserves that choice rather than forcing a cursor image.
Leaving the client restores shell cursor ownership. No cursor artwork, theme or
size policy changes accompany pointer constraints. XWayland's X11 pointer grabs
and XFixes cursor hiding use this same native path.

The focused real-protocol suite exercises native lock activation, raw relative
movement without absolute motion, cursor hiding, committed unlock hints,
keyboard focus changes, workspace visibility, one-shot lifetime, scaled
confinement and region commits, unmapping, host focus loss, remote-seat isolation,
and a private XWayland client's grab/hide/move/release sequence:

```sh
cargo test -p weldwm -p weld-core --lib pointer_ -- --include-ignored --test-threads=1
```

It requires the normal native development environment and XWayland. It uses
private sockets and synthetic input; it does not establish physical-device or
individual-game acceptance. The geometry and nested raw-motion tests run without
the ignored native fixtures.
